# AI-помощник и агентная архитектура

Модуль `app/agents.py` реализует этапы AI-помощника из ТЗ: уточнение исходного запроса и сборку редактируемой карточки. Здесь нет дополнительных продуктовых функций, автоматического выбора команды или скрытого начисления рейтинга.

## Агенты и оркестрация

`AgentOrchestrator` передаёт типизированные данные между четырьмя независимыми ролями:

1. **AnalysisAgent** проверяет формат и размер описания, отрасли, полей и ответов; определяет недостающие сведения.
2. **InterviewAgent** выбирает вопросы по этим пробелам. Внешняя модель, если настроена, уточняет формулировки. Всегда остаётся минимум три вопроса. Если карточка уже полная, задаются вопросы для проверки данных, ограничений и критериев успеха.
3. **CompositionAgent** собирает все десять полей карточки. Адресные ответы переносятся только в соответствующие поля, ранее введённые сведения сохраняются. Модель может распределять точные цитаты из исходного описания по недостающим полям.
4. **ValidationAgent** проверяет JSON, поля, размеры и источники. Ответ модели с выдуманным фактом, изменённым ответом пользователя, неверной структурой или пропущенным обязательным полем отклоняется полностью.

Это ограниченный последовательный процесс агентов, а не автономные агенты с доступом к компьютеру или внешним инструментам. Анализ и проверка детерминированы; внешняя языковая модель используется в роли интервьюера и составителя. Без подключения модели эти роли работают по локальным правилам. Трасса показывает фактически выполненные этапы и факт резервного режима, без скрытых рассуждений.

```text
Описание → анализ → вопросы → ответы бизнеса
                              ↓
              составление → проверка → редактируемая карточка
```

Проверка источника подтверждает происхождение строки, но не истинность утверждения пользователя и не безошибочность смысловой классификации. Поэтому человек редактирует и явно подтверждает поля перед публикацией. Сама агентная система ничего не публикует и не подтверждает.

## Запуск без AI API

Никакой конфигурации не требуется. При отсутствии `AI_API_KEY` приложение работает без сети и без платных API-вызовов:

- вопросы выбираются по незаполненным полям; первый содержит цитату из описания;
- название — короткий фрагмент исходного описания;
- контекст — исходное описание, до лимита поля;
- потребность — только предложение, содержащее явный сигнал потребности, например «хотим» или «нужно»;
- остальные неизвестные сведения остаются пустыми; целевые ответы заполняют соответствующие поля.

Режим всегда обозначен как `local` и сопровождается предупреждением «Локальный режим без языковой модели». Это работающий резервный сценарий, а не имитация внешнего AI. Для демонстрации именно языковой модели настройте API.

## Подключение внешней модели

Используется совместимый с Chat Completions сервер: HTTPS, `POST /chat/completions`, JSON-ответ модели. Ключ хранится только на сервере. Для локального провайдера разрешён HTTP на `localhost`, `127.0.0.1` или `::1`. Перенаправления HTTP отключены, чтобы ключ не переходил на другой адрес.

Скопируйте `.env.example` в `.env`, заполните ключ и название модели, поддерживающей JSON mode и `max_completion_tokens`, затем запустите `python3 server.py`. Сервер автоматически читает переменные `AI_*` из `.env`; уже заданные переменные окружения имеют приоритет. Модуль агентов отдельно `.env` не читает. Не добавляйте `.env` в Git. Альтернатива — экспортировать переменные в терминале:

```sh
export AI_API_KEY='ваш-ключ'
export AI_MODEL='имя-доступной-вам-модели'
export AI_BASE_URL='https://api.openai.com/v1'
export AI_TIMEOUT_SECONDS='15'
python3 server.py
```

Для локального OpenAI-совместимого сервера, которому не нужна авторизация, задайте произвольный непустой `AI_API_KEY` (например `local`), его адрес `/v1` и реальное имя модели. Поддержка всех параметров зависит от провайдера; несовместимый ответ честно переключает запрос в локальный режим.

| Переменная | Значение |
|---|---|
| `AI_MODE` | `auto` по умолчанию; `local` принудительно отключает внешнюю модель даже при наличии ключа |
| `AI_API_KEY` | Пусто по умолчанию. При `AI_MODE=auto` непустое значение включает попытку настройки API |
| `AI_MODEL` | Обязательное явное имя доступной модели; значения по умолчанию нет |
| `AI_BASE_URL` | По умолчанию `https://api.openai.com/v1`; без завершающего `/chat/completions` |
| `AI_TIMEOUT_SECONDS` | По умолчанию 15; общий срок ожидания вызова и тайм-аут сетевых операций, в диапазоне 1–30 секунд |

При сетевой ошибке, отказе модели, некорректной конфигурации, обрезанном ответе или провале проверки источников возвращается локальный результат с пояснением. Автоматических повторных платных вызовов нет. Текст ошибки провайдера и ключ не выдаются клиенту. Общий срок ожидания защищает интерфейс даже при медленной передаче ответа. Одновременно допускаются максимум четыре фоновых запроса к модели; остальные операции используют локальный режим. После тайм-аута сетевой запрос может ещё завершаться в фоновом потоке, но пользователь уже получает локальный результат; потоки не задерживают завершение приложения.

`AgentOrchestrator.mode` описывает **настроенный** режим. Поле `mode` в результате конкретного вызова отражает **фактический** режим этого вызова, включая откат в `local`.

Код запроса основан на [официальном описании Chat Completions](https://developers.openai.com/api/reference/resources/chat). В пакете нет ключа; платные вызовы и доступность конкретной модели при подготовке архива не проверялись. Автотесты подменяют сетевой клиент.

## Контракты и промпты

Полные системные промпты находятся в константах `QUESTION_PROMPT` и `COMPOSITION_PROMPT` в исходном коде. Они отделены от пользовательских данных отдельным сообщением `system`. Данные описания и ответов передаются как JSON в `user`; инструкции внутри них считаются данными.

Вопросы получают `draft`, `industry`, `fields`, `allowed_questions`. Формат ответа модели:

```json
{
  "questions": [
    {"field": "data", "text": "Какие исходные файлы вы можете предоставить?"},
    {"field": "users", "text": "Кто будет пользоваться результатом?"},
    {"field": "success", "text": "Как вы проверите, что результат подходит?"}
  ]
}
```

Вопросы имеют уникальные целевые поля. Пропущенные моделью вопросы по другим недостающим полям дополняются локальными. В ответе приложения каждый вопрос получает `id`, равный `field`.

Составление получает `draft`, `industry`, `answers`, `fields`, `field_names`. Модель обязана вернуть ровно десять ключей: `title`, `context`, `need`, `users`, `data`, `constraints`, `outcome`, `success`, `contact`, `interaction`. Каждый имеет структуру:

```json
{"value": "CSV с продажами за май", "source": "answers.data"}
```

Допустимые источники:

- `answers.FIELD` — точная строка ответа на вопрос об этом же поле;
- `fields.FIELD` — точная строка ранее введённого значения того же поля;
- `draft` — точная непрерывная цитата из исходного описания для незаполненного поля;
- пустая строка — только для неизвестного, пустого значения.

Адресный ответ имеет приоритет над прежним значением. Если ответ пустой или явно сообщает «не знаю» / «не указано», он не заменяет ранее введённые сведения. Формулировка «Данных нет» сохраняется как явное сообщение бизнеса, без выдуманных материалов. Для очистки поля используется ручное редактирование карточки.

Внешний API возвращает оболочку Chat Completions: один `choices[0]`, `finish_reason: "stop"`, `message.content` со строкой JSON. Дубликаты ключей, `NaN`, отказ модели, незавершённый вывод и неверные типы отклоняются.

## Ограничения

- Исходное описание: до 12 000 символов.
- Отрасль: до 120 символов.
- Название: до 180 символов.
- Остальные поля и ответы: до 4 000 символов каждый.
- Ответ внешнего API: до 180 000 байт.
- Один вызов API на операцию вопросов или составления.
- Резервное составление сохраняет полное исходное описание в задаче, но помещает только первые 4 000 символов в поле контекста. Карточку можно поправить вручную.
- Точная цитата ограничивает возможности литературного переформулирования намеренно: неподтверждённые сведения в карточку не добавляются.

## Проверка

```sh
python3 -m unittest tests.test_agents -v
```

Тесты проверяют минимум три вопроса и связь с контекстом, заполненные карточки, сохранение ручных правок, целевое распределение ответов, отсутствие выдуманных данных, границы ввода, некорректные JSON/схемы, тайм-ауты, честный резервный режим, проверку источников и формат HTTP-запроса. Во время этих тестов сетевых запросов нет.
