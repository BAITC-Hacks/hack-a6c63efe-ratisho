# HackAlem · Задачи для команд

Работающий MVP по кейсу AI Sana: бизнес уточняет задачу, подтверждает карточку, получает прозрачный рейтинг и публикует её в общем каталоге. Студенческие команды подают предложения; бизнес выбирает одну, несколько или ни одной команды. Баллы команды начисляются за подтверждённый этап.

Реализованы требования [исходного кейса](https://docs.google.com/document/d/1lFWekP2SirFarATKkWa5neHNL5DlhjZKkUacvGyZk8k/preview). Дополнительные продуктовые инновации из предварительного плана не включены.

## Быстрый запуск

Нужен **Python 3.9 или новее** с SQLite (входит в обычную установку Python). Не нужны Node.js, npm, pip-пакеты, Docker или ключ API. Все интерфейсные ресурсы включены в проект; шрифты и скрипты не загружаются с CDN.

```sh
python3 server.py
```

В Windows:

```powershell
py -3 server.py
```

Откройте **http://127.0.0.1:8000**. Для остановки нажмите `Ctrl+C`. Если порт занят, запустите `python3 server.py --port 8001` и откройте соответствующий адрес.

Не открывайте `static/index.html` двойным кликом: интерфейсу нужен сервер для сохранения данных.

При первом запуске автоматически создаётся `data/hackalem.sqlite3` и загружаются синтетические примеры. Изменения сохраняются между перезапусками. Для отдельной чистой демонстрации укажите новый путь, не удаляя старые данные:

```sh
python3 server.py --port 8001 --db data/demo-new.sqlite3
```

## Как пользоваться

1. В режиме **Бизнес** создайте задачу: введите описание и тему.
2. Получите уточняющие вопросы. Укажите известные сведения; неизвестные можно оставить пустыми.
3. Сформируйте карточку. Все десять полей можно редактировать. Подтвердите заполненные поля, чтобы они учитывались в рейтинге.
4. Сохраните карточку и отдельно подтвердите её публикацию. Заполнение всех полей и высокий рейтинг не являются условием публикации.
5. Переключитесь в режим **Команда**, выберите один из пяти профилей. В каталоге откройте задачу и отправьте идею, план, срок и ссылку на прототип.
6. Вернитесь в **Бизнес**, сравните предложения и вручную выберите или отклоните их. Допускается выбор нескольких команд.
7. Выбранная команда отправляет один завершённый этап со ссылкой на результат. После подтверждения бизнесом получает 10 баллов. Повторное подтверждение не увеличивает баллы.

Переключение ролей — демонстрационный механизм из объёма MVP, **не система аутентификации**. Все бизнес-задачи принадлежат одному демонстрационному кабинету. Сервер слушает только локальный адрес; проект не предназначен для прямой публичной эксплуатации с реальными персональными данными.

## Формула рейтинга

Рейтинг рассчитывает обычный код, независимо от ответов AI. Заполненное поле без ручного подтверждения даёт **0 баллов**. Пустые значения и заглушки вроде «Не указано» не считаются заполнением.

| Категория | Максимум | Правило |
|---|---:|---|
| Контекст и потребность | 20 | Контекст 10 + потребность 10 |
| Данные и материалы | 20 | Заполненное и подтверждённое поле |
| Ожидаемый результат | 15 | Заполненное и подтверждённое поле |
| Критерии успеха | 15 | Заполненное и подтверждённое поле |
| Ограничения | 10 | Заполненное и подтверждённое поле |
| Пользователи | 10 | Заполненное и подтверждённое поле |
| Связь с бизнесом | 10 | Контакт 5 + формат взаимодействия 5 |

Название обязательно для публикации, но баллов не даёт. Это оценка полноты подтверждённого описания, а не автоматическая проверка истинности заявления или репутации компании.

Уровни: **0–39 — черновик**, **40–69 — рабочая**, **70–89 — готовая**, **90–100 — приоритетная**. В интерфейсе показаны категории, начисленные баллы, недостающие сведения и рекомендации по заполнению. При редактировании поля интерфейс снимает его подтверждение; бизнес может подтвердить новое значение. После сохранения сервер пересчитывает рейтинг.

## Правила каталога и выбора

- В общем каталоге показаны все **опубликованные** карточки, включая уровень «Черновик» с 0–39 баллами. Неопубликованный рабочий черновик виден только в кабинете бизнеса.
- Сортировка — по убыванию рейтинга; при равенстве порядок стабилизируется идентификатором. Есть фильтры по теме и уровню готовности.
- Низкий рейтинг не блокирует отклик. Фильтры можно сбросить, чтобы увидеть весь каталог.
- Нет автоматического назначения, закрытого подбора, ограничения количества откликов или выбора только одной команды.
- Предложение содержит идею, план, срок и HTTP(S)-ссылку. Проверяется формат ссылки, а не доступность внешнего прототипа.
- Баллы студенческой команды отделены от рейтинга задачи. Для минимального этапа используется правило +10 за подтверждённый результат. Начисление атомарно и однократно.

## Мультиагентная обработка и AI

В `app/agents.py` реализован оркестратор с четырьмя компонентами:

```text
Описание и текущие поля
        ↓
AnalysisAgent — проверяет вход и недостающие сведения
        ↓
InterviewAgent — формирует минимум три уточняющих вопроса
        ↓
Ответы пользователя
        ↓
CompositionAgent — собирает редактируемую карточку
        ↓
ValidationAgent — проверяет структуру и опору на исходные сведения
        ↓
Ручное подтверждение → детерминированный рейтинг → публикация
```

**По умолчанию работает разрешённая ТЗ локальная заглушка без языковой модели.** Её компоненты используют детерминированные правила, вопросы по недостающим полям и прямой перенос ответов. Интерфейс явно сообщает о локальном режиме. Это позволяет запустить и защитить весь сценарий без внешнего сервиса; локальный режим не выдаётся за вызов LLM.

Реальная языковая модель подключается через совместимый Chat Completions API. Скопируйте `.env.example` в `.env`, укажите свои `AI_API_KEY`, `AI_MODEL` и при необходимости `AI_BASE_URL`, затем перезапустите сервер. Ключ остаётся на сервере и не передаётся браузеру. При включённом внешнем режиме описание задачи и ответы отправляются указанному провайдеру; для демонстрации используйте синтетические данные.

Невалидный ответ, тайм-аут или ошибка провайдера приводят к локальному резервному режиму с видимым предупреждением. Внешняя генерация карточки ограничена цитатами из предоставленных сведений; выдуманные или неподтверждённые моделью сведения отклоняются. AI не публикует карточки, не подтверждает поля, не начисляет баллы и не выбирает команду.

Промпты, входной/выходной JSON, переменные окружения и обработка ошибок: [docs/AI.md](docs/AI.md).

## Архитектура

```text
static/                HTML, CSS, JavaScript; без сборки и внешних зависимостей
server.py              HTTP API, раздача статических файлов, загрузка .env
app/store.py           SQLite, транзакции и допустимые переходы состояния
app/domain.py          поля, валидация, веса и уровни рейтинга
app/agents.py          оркестратор и четыре компонента обработки
app/seed.py            воспроизводимые синтетические данные
tests/                 unit-тесты и сквозные HTTP-тесты
docs/                  контракт API, AI, матрица требований, сценарий защиты
.github/workflows/     автоматическая проверка после push / pull request
```

Данные хранятся на сервере в SQLite, а не только в памяти браузера. Запись выполняется в транзакциях. Номер ревизии защищает карточку от перезаписи устаревшей вкладкой: при конфликте сервер возвращает 409. Клиент не должен молча перезаписывать новую версию. Баллы команды вычисляются из подтверждённых этапов.

Никакие чувствительные признаки людей не используются. В демонстрационных профилях есть только название команды, интересы, навыки и технологии. Контакты и ссылки `example.com` синтетические и не являются готовыми реальными прототипами.

## Тесты

```sh
python3 -m unittest discover -s tests -v
```

Тесты создают временную базу и локальный HTTP-сервер на свободном порту. Они не изменяют вашу рабочую базу и не обращаются к внешнему AI. Для их запуска среда должна разрешать локальные сетевые подключения.

Проверяются формула и уровни, подтверждения, невалидные данные, набор примеров, AI-ответы и резервный режим, полный HTTP-сценарий, публикация с нулевым рейтингом, несколько выбранных команд, права демонстрационных ролей, сохранение после повторного открытия базы и конкурентное однократное начисление баллов.

Ручные сценарии и соответствие пунктам ТЗ: [docs/REQUIREMENTS.md](docs/REQUIREMENTS.md). Сценарий выступления: [docs/DEMO.md](docs/DEMO.md).

Фактически выполненные проверки и их границы: [docs/TEST_REPORT.md](docs/TEST_REPORT.md).

## Загрузка в GitHub

Распакуйте архив и загрузите **всё содержимое папки `hackalem`**, включая `.gitignore`, `.env.example` и `.github`. Если репозиторий уже существует, перенесите файлы в него и создайте коммит. Для нового локального репозитория:

```sh
git init
git add .
git commit -m "feat: implement HackAlem MVP"
git branch -M main
git remote add origin https://github.com/YOUR_ACCOUNT/YOUR_REPOSITORY.git
git push -u origin main
```

Замените адрес своим репозиторием. Не загружайте `.env`, рабочую базу данных или кэш Python — они исключены через `.gitignore` и не включены в поставляемый архив.
